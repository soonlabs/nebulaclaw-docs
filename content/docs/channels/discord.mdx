NebulaClaw now supports **Discord** as a messaging channel. Like Telegram, Bots are hosted by the platform — **you don't need to create an Application in the Discord Developer Portal and you never handle a Bot Token**.

## Prerequisites

- A purchased Bot ($9.99 / Bot) with persona and model configured
- A Discord account with **Manage Server** permission on the target server (OAuth invite must be performed by an account that has this permission)

## Connect Discord

<Steps>
  <Step title="Open the Platforms page">
    In the console, go to **Agent → Platforms** and switch to the **Discord** tab.
  </Step>

  <Step title="Click Connect Discord">
    You'll see a purple **Connect Discord** button. One click kicks off three phases automatically:

    1. Allocating bot from pool
    2. Configuring gateway
    3. Finalizing connection

    When it finishes, a **Connected** card appears with the Bot's `@username`.
  </Step>

  <Step title="Invite the Bot to your server">
    On the Connected card, click **Invite to Server** — this opens Discord's official OAuth authorization page:

    - Select your server from the dropdown
    - Review the requested permissions (moderation scopes are pre-requested) → **Authorize**
    - Pass the CAPTCHA

    <Note>Only servers where you have **Manage Server** permission appear in the dropdown.</Note>
  </Step>

  <Step title="Register the Server ID">
    Back on Platforms → Discord, scroll down to the **Discord Servers** section and click **Add Server**. A three-step dialog walks you through:

    1. Confirm the Bot is in the target server (if not, re-open the invite link from the dialog)
    2. Copy the Server ID from Discord (Developer Mode → right-click the server icon)
    3. Paste it into the input, optionally give it a friendly name, then click **Add Server**

    Once added, the server appears in the list with a status tag: **Ready / Syncing / Sync error**.
  </Step>
</Steps>

## Getting Server / Channel IDs

Discord IDs are 17–20 digit numeric snowflakes. You need to turn on Developer Mode first.

<Steps>
  <Step title="Enable Developer Mode">
    Discord → **User Settings → Advanced → Developer Mode**, toggle on.
  </Step>
  <Step title="Copy the Server ID">
    In the left server sidebar, right-click the server icon → **Copy Server ID**.
  </Step>
  <Step title="Copy a Channel ID">
    Inside the server, right-click a channel name → **Copy Channel ID**. Only needed if you want per-channel overrides.
  </Step>
</Steps>

<Tip>Guild and Channel IDs are 18–19 digit integers with **no leading minus** — unlike Telegram's `-100...` supergroup format.</Tip>

## Default behavior and channel overrides

After you register a server, the default config applies to **every channel the Bot can see** in that server:

- **Require @mention to reply** (on by default) — Bot responds only when `@BotName` is mentioned
- **Fallback Language = auto** (language auto-detected per message)

> Discord channels typically carry much higher message volume than Telegram groups. **Keep Require Mention on** unless you know what you're doing — otherwise token usage will spike.

### Channel overrides

To tune behavior for a specific channel (e.g. drop the @mention requirement in #announcements, pin a fallback language in #welcome), expand the server row → click **Add channel**:

1. Paste the Channel ID (right-click channel → Copy Channel ID)
2. Optional: channel name for display
3. Toggle **Require @mention to reply**
4. Pick a **Fallback Language**

> Channels without an override keep following the server default. Overrides can be removed anytime to fall back.

### Fallback Language options

**Follow user** (default, "auto") / English / Simplified Chinese / Korean / Turkish / Indonesian / Russian / Vietnamese

<Note>Per-server and per-channel settings can only be modified while the Bot is online. The config area is read-only when the Agent is suspended or still booting.</Note>

## FAQ

<AccordionGroup>
  <Accordion title="Bot isn't replying in my server">
    Check in order: ① **Agent → Platforms → Discord** shows **Connected**; ② Bot is visible in the server's member list (invited via OAuth); ③ Server ID is registered in **Discord Servers** with status **Ready**; ④ Bot has View Channel + Send Messages permission in the target channel; ⑤ By default the Bot requires `@BotName` — to reply without @, add a channel override with Require @mention off.
  </Accordion>
  <Accordion title="Add Server says the Bot isn't in the server">
    The backend detected that the Bot hasn't joined that Guild yet. In the dialog, click **Open invite link** and re-authorize through Discord's OAuth, then paste the Server ID again.
  </Accordion>
  <Accordion title="Server status stuck on Syncing or Sync error">
    Sync is when the Bot backend pulls the channel list for the server. It's usually done within seconds. If it hangs: check that the Bot wasn't kicked, and its role hasn't been denied View Channel. When in doubt, remove and re-add the server.
  </Accordion>
  <Accordion title="Bot can talk but can't kick / timeout members">
    Moderation permissions (Kick / Ban / Moderate Members) are requested during the OAuth invite. If actions still fail: ① in **Server Settings → Roles**, verify the Bot's role has the permission enabled; ② the Bot's role must sit **above** the target member's highest role — Discord forbids acting on equal-or-higher roles, and the server owner can never be moderated.
  </Accordion>
  <Accordion title="I want one channel to reply without @, the rest to keep requiring @">
    Add a channel override: expand the server row → **Add channel** → paste that channel's ID → turn off Require @mention → Add. Only that channel changes; the rest follow the server default.
  </Accordion>
  <Accordion title="Can one Bot manage multiple Discord servers?">
    Yes. Under the same Agent, the **Discord Servers** list can hold multiple Server IDs. Each server manages its own channel overrides.
  </Accordion>
  <Accordion title="What if my Bot gets compromised? Is it safe?">
    Whether the Bot is hosted on NebulaClaw or created by you via the Discord Developer Portal, token leakage is theoretically possible. Platform-hosted Bots use controlled key storage and access auditing, so the probability is lower.

    **Recovering a leaked token**:

    - **Platform-hosted Bot (allocated by NebulaClaw)**: contact support — we reset the token in the Developer Portal and rotate it automatically
    - **Self-hosted Bot (if you're using your own Application)**: open the [Discord Developer Portal](https://discord.com/developers/applications) → select your Application → **Bot → Reset Token** → confirm 2FA; the old token is invalidated immediately

    **Security boundary**:
    - Outsiders **cannot DM the Bot to do anything** — moderation actions are Bot-initiated; the only attack surface is the token itself
    - Signing into the Developer Portal requires your Discord password + 2FA, so as long as your Discord account isn't compromised, you can reset the Bot anytime
    - As long as the Bot token isn't leaked, the Bot is safe
  </Accordion>
</AccordionGroup>
